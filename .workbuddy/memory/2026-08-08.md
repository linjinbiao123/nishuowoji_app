### 算法对齐要点（改动此文件前必读）
1. **payload 必须手工拼接**，字段顺序 `v, exp, dev, iat`，无空格：
   `{"v":1,"exp":<int>,"dev":"<hex>","iat":<int>}`
   与 Dart `jsonEncode` 的插入顺序输出一致。通用卡 `dev` 为空串 `""`。
2. **签名为 r‖s 各 32 字节定长大端 = 64 字节**（非 DER）。
   对应 App 端 `VipCrypto._sigToBytes`；Node 侧用 `dsaEncoding:'ieee-p1363'` 即同格式。
3. **base64url 必须保留 `=` padding**。Dart `base64Url.decode` 遇长度非 4 倍数会抛
   `FormatException` → 卡密直接作废。这是最容易踩的坑。
   （注意 JWK 里的 base64url 规则相反，必须去 padding，别搞混。）
4. 卡密 = `b64u(payload) + "." + b64u(sig)`。

### 实现选择及原因
- **纯 JS 实现 SHA-256 / HMAC / P-256 ECDSA，不用 `crypto.subtle`**。
  原因：`file://` 下 WebCrypto 在部分移动浏览器/WebView 不是安全上下文，会直接不可用。
  纯 BigInt 实现任何环境都能跑（需 BigInt：Chrome 67+ / Safari 14+）。
- **RFC 6979 确定性 k**，不依赖随机源。附带好处：同输入同输出，可逐字节复现验证。
- P-256 用雅可比坐标 + 扩展欧几里得模逆，签发约 9ms（桌面 Node），手机上无感。

### 页面自带的防呆设计
- 启动自检：跑 RFC 6979 官方向量（A.2.5），失败则**禁止生成**，避免发出废卡。
- 私钥输入后自动推导公钥，与 App 内置公钥比对，不匹配直接红字拦截。
- 每张卡生成后**用 App 内置公钥本地验签**，验不过就不输出。
- 「查询已有卡密」：粘贴任意卡密 → 显示绑定设备/到期/签发时间/剩余天数（售后排查用）。
- 私钥可选存 localStorage（`shuoji_vip_priv`），有「清除」按钮。
